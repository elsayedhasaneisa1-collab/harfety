# حرفتي — HTML / CSS / JavaScript + Supabase

تم حذف Next.js وReact وTypeScript وDrizzle وملفات التطوير/التجربة من هذه الحزمة. المشروع واجهة ثابتة تستخدم JavaScript modules وSupabase JS من CDN.

## محتويات المشروع
- `index.html`: بوابة تتحقق من الجلسة والدور قبل فتح لوحة الإدارة.
- `auth/login.html`: تسجيل الدخول برقم الهاتف وكلمة المرور.
- `auth/register.html`: إنشاء حساب حرفي مع الاسم والهاتف وكلمة المرور والحرفة والمدينة والخبرة والنبذة.
- `assets/js/register.js`: إنشاء الحساب عبر Supabase Auth؛ لا يخزن كلمة المرور في جدول مخصص.
- `owner/index.html`: لوحة الإدارة وإدارة الحرفيين والأعمال والرسائل.
- `crafts/index.html`: صفحة حساب الحرفي؛ لا تمنح صلاحيات الإدارة.
- `assets/css/style.css`: التصميم المتجاوب.
- `assets/js/supabase-config.js`: مكان إضافة رابط المشروع والمفتاح العام.
- `assets/js/auth.js`: تسجيل الدخول وفحص الدور.
- `assets/js/owner.js`: وظائف لوحة الإدارة.
- `sql/supabase-schema.sql`: الجداول والقيود وسياسات RLS، بدون بيانات تجريبية.

## الإعداد
1. افتح `assets/js/supabase-config.js` وضع `Project URL` و`Publishable key` (أو anon key القديم) فقط.
2. في Supabase SQL Editor نفّذ `sql/supabase-schema.sql`. لا تشغله فوق قاعدة بيانات إنتاجية موجودة دون مراجعة/نسخة احتياطية؛ قد تتطلب بياناتك القديمة ترحيلًا.
3. من Supabase Authentication أنشئ مستخدم المسؤول يدويًا، ثم أضف إلى **App Metadata** لهذا المستخدم: `{ "role": "admin" }`. لا تستخدم `user_metadata` لهذا الغرض.
4. فعّل Phone provider في Supabase Authentication، ثم عطّل خيار Confirm phone / Phone confirmations حتى يتم التسجيل والدخول برقم الهاتف وكلمة المرور دون SMS أو رمز تحقق. إذا ظل تأكيد الهاتف مفعّلًا، فلن يستطيع المستخدم إنشاء جلسة دخول مباشرة. حسابات الحرفيين تُنشأ من صفحة التسجيل، وتُسجل حالتها pending لمراجعة الإدارة. حساب الإدارة فقط يحصل على app_metadata.role=admin. لا تضع أي مفاتيح سرية داخل ملفات المتصفح.
5. استضف المجلد على استضافة ملفات ثابتة (مثل HTTPS static hosting). لا تفتح الملفات مباشرة بـ `file://`؛ استخدم الاستضافة أو خادمًا محليًا.
6. اختبر الدخول، إضافة/تعديل/حذف السجلات، ومحاولات الوصول بحساب غير إداري قبل البيع.

## حدود أمنية مهمة
- واجهة HTML لا يمكنها إخفاء الأكواد أو منع شخص من تنزيل الملفات؛ الحماية الحقيقية هنا هي سياسات RLS والتحقق من `app_metadata.role` داخل JWT.
- مفتاح Supabase publishable/anon مخصص للمتصفح، لكنه ليس سرًا؛ RLS ضروري.
- تسجيل حساب الحرفي متاح برقم الهاتف وكلمة المرور. التسجيل لا يستخدم SMS أو رمز تحقق؛ عطّل Confirm phone في إعدادات Supabase Authentication. هذا إعداد مطلوب في لوحة Supabase ولا يمكن فرضه من HTML وحده. لا توجد في هذه النسخة مصادقة ثنائية إضافية أو رفع ملفات. رابط الصور يجب أن يكون HTTPS.
- لم يتم ترحيل حسابات/جلسات/بيانات Next.js القديمة تلقائيًا. هذا تحويل للواجهة وبنية Supabase، وليس ضمانًا بأن بيانات قاعدة البيانات القديمة متوافقة مباشرة.
- قبل البيع التجاري: نفّذ مراجعة أمنية مستقلة واختبار صلاحيات/نسخ احتياطي؛ لا توجد حماية مطلقة أو ضمان خلو من الثغرات.
